# 电力交易模拟器 ETS

面向内部交易演练的电力市场仿真系统。覆盖**中长期**（年度 / 月度 / 月内多日）与**日前现货**两大品种，
支持**双边协商、集中竞价、挂牌摘牌、滚动撮合、现货集中出清**五种交易方式。
除真人交易外，盘中始终有一批**交易机器人在实时报价、撮合、挂牌摘牌与现货申报**，保证盘面随时是活的。

## 技术栈

| 层 | 选型 |
|---|---|
| 后端 | Spring Boot 4.1.0 · Java 17 · 原生 WebSocket |
| 运行时存储 | Redis 8.0.5（`10.0.0.12:6379`，**db 3**，前缀 `ets:`） |
| 归档存储 | MySQL（默认关闭，DDL 见 `ets-service/src/main/resources/db/schema.sql`） |
| 前端 | Vue 3.5 · Vite 8 · Ant Design Vue 4 · ECharts 6 · Pinia 4 · Vue Router 5 |

> Redis 的 db0 已被其它应用占用，本系统一律使用 **db 3**，所有 key 以 `ets:` 开头，
> 因此管理端的「重置演练」不会影响到同一实例上的其它业务。

## 快速开始

三个终端分别执行：

```bash
# 后端（Windows PowerShell）
cd ets-service
.\mvnw.cmd spring-boot:run

# 用户端
cd userDist
npm run dev          # http://localhost:5173

# 管理端
cd adminDist
npm run dev          # http://localhost:5174
```

前端已配置代理，`/api` 与 `/ws` 自动转发到 `http://localhost:8080`，无需额外配置跨域。

## 一次完整的演练流程

1. **管理端** 新建模拟盘 → 一键生成标准场次（或手工逐个配置品种、时段、交易方式、涨跌幅、交割区间）。
2. **用户端** 在模拟盘处于「筹备中」时，每个用户可以创建**多个交易账户**，
   按主体类型（发电企业 / 电力用户 / 售电公司）分别设定初始资金、装机容量与变动成本、
   年度电量或用电需求、可承受价、负荷特性、单笔与持仓限额等参数。
3. **管理端** 点「开盘」——此刻起：
   - 所有交易账户按初始资金完成注资，**参数被永久锁定，任何人不得再修改或删除**；
   - 24 台交易机器人自动上场，覆盖六种策略与三类市场主体；
   - 场次按真实时间（1:1）依次开市，集中竞价与现货进入集中申报期。
4. **交易中** 真人与机器人在同一撮合引擎里竞争。管理员可随时注入市场事件
   （燃料涨价、负荷激增、机组非停、极端天气……）、直接调整基本面、发布公告、临时停牌。
5. **结算** 按周期出结算单：合同电量与电费、实际交割、偏差考核、现货电费、手续费、盈亏与排名。

## 交易方式说明

| 方式 | 机制 |
|---|---|
| 滚动撮合 | 连续竞价，价格优先 / 时间优先，成交价取先到方（Maker）报价，支持 GFD / GTC / IOC / FOK |
| 集中竞价 | 集中申报期只收单不撮合、盘口保密；到点求最大成交量对应价格，全部按**统一出清价**成交，边际单按比例分配 |
| 挂牌摘牌 | 一方挂牌、对手方摘牌即成交，成交价即挂牌价；支持最小摘牌量与「必须整量摘取」，不可摘自己的牌 |
| 双边协商 | 邀约 → 还价 → 接受 / 拒绝，轮流进行最多 10 轮，达成即签合同；不影响公开行情的最新价 |
| 日前现货 | 提交 24 点报价曲线，每个小时段独立出清（供给曲线升序 × 需求曲线降序求交点） |

## 配置

关键配置都在 `ets-service/src/main/resources/application.yml`：

```yaml
ets:
  bootstrap:
    admin-username: admin        # 内置管理员
    demo-data: true              # 首次启动生成演示数据
  robot:
    enabled: true                # 机器人总开关
    threads: 8
  market:
    quote-push-interval-ms: 1000 # 行情推送节流
  mysql:
    enabled: false               # MySQL 归档开关
```

### 启用 MySQL 归档

MySQL 当前不可达，因此默认全部数据只走 Redis。数据库就绪后：

1. 建库并执行 `ets-service/src/main/resources/db/schema.sql`；
2. 把 `ets.mysql.enabled` 改为 `true`，填好 `url` / `username` / `password`；
3. 重启服务，成交、合同、结算单等会异步批量落库。

归档层用纯 JDBC 手写，不引入 JPA / MyBatis，也不注册 `DataSource` 自动配置——
这样数据库不可用时服务依然能正常启动。

## 已知取舍

- 时钟严格实时 1:1。`sim.clockSpeed` 字段已保留但当前按 1 处理，需要加速演练时再启用。
- 撮合订单簿的权威结构在 JVM 内存，Redis 只做镜像，因此**当前是单实例部署**。
  多实例需要把账户级分段锁换成 Redis 分布式锁，并按场次做分片路由。
- 排行榜按账户累计盈亏排序，结算单里的名次按当期利润排序，两个口径刻意分开。
